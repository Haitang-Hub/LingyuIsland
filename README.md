# 灵屿岛

一款「灵动岛」风格的桌面文件屏蔽工具：把文件拖到屏幕顶部的胶囊上，自动识别内容并生成屏蔽副本或还原副本；屏蔽产物统一为「原文件名_屏蔽」，还原产物统一为「原文件名_还原」。文本/Office 屏蔽值内嵌还原编码，**只要编码未被改动（哪怕从文件里复制出来），随时可一键还原真实内容**。PDF / 图片为不可逆遮盖，同样生成 `_屏蔽` 副本，但不支持还原。

> 隐私设计原则：**性别、年龄、出生日期等依法用于判断的信息不作为敏感信息，不会屏蔽**；身份证号属于个人身份标识，仍会屏蔽（屏蔽后保留首尾特征，可判断内容类型）。

## 功能

| 功能 | 说明 |
| --- | --- |
| 拖入即处理 | 拖文件/文件夹到屏幕顶部胶囊，**按内容及映射库自动判断**：明文 → 生成 `文件名_屏蔽.ext`，含**可还原编码**（映射库中查得到）的屏蔽文件 → 生成 `文件名_还原.ext`；仅有编码外观但库里查不到的明文（如测试样例 `〔姓名·abcdef〕`）仍按屏蔽处理；产物文件名（`_屏蔽`/`_还原`）在映射库缺失时仍走还原并提示无法还原的编码；**直接读取源文件，只在根目录写出结果，不生成原文件副本**，原位置的文件不会被改动（可在设置中改为处理后移入回收站）；结果文件同名时可选保留两份或覆盖，完成后胶囊与面板都会给出结果提示 |
| 可还原的屏蔽 | 屏蔽形如 `138****5678〔手机号·a3f2b1〕`：保留首尾特征 + 类型标签可判断内容，`〔〕`内编码是还原钥匙 |
| 随时还原 | 把屏蔽文件重新拖入即可自动生成 `文件名_还原.ext`（编码需在映射库中；映射库丢失时可在「文本恢复」页粘贴还原）；粘贴任意含编码的文本可实时还原 |
| 剪贴板恢复 | 复制了含编码的内容时，胶囊提示「识别到含屏蔽信息」，点右侧「还原文本」按钮才还原并写回剪贴板；仅对当前复制的那段文本生效，剪贴板换成别的内容后提示自动失效 |
| 编码防篡改 | 编码被改动时明确提示无法还原，绝不输出错误内容 |
| 快速查找 | 配置根目录后自动建索引、监听变更，秒搜根目录下所有文件；可按「全部/文档/表格/图片/文本/其他」筛选（按钮上的数字为该类别命中数；代码等未列类型归入其他），结果可打开或在文件夹中定位 |
| 全类型支持 | 文本类（txt/md/csv/json/代码等，UTF-8/GBK 自动识别）+ Office（docx/xlsx/pptx）+ 老式 `.doc/.dot`（本地自动转换为 .docx 后处理，结果以 .docx 落地）+ PDF（不可逆遮盖：文本层或 OCR 定位敏感区域 → 整页栅格化涂黑，输出 `_屏蔽` 无文本层 PDF，不支持还原）+ 图片（jpg/png/webp 等：内置 OCR 识别文字 → 涂黑敏感区域 → 重新编码输出 `_屏蔽` 图片，不支持还原） |
| 多分辨率适配 | 按显示器工作区与系统缩放自动等比调整胶囊/面板，窗口始终完整落在屏幕内（恒为自适应，无需手动选择） |

## 敏感信息检测范围

- ✅ 手机号（含校验边界）、身份证号（18 位结构校验；文书里校验码不合法的虚构号也覆盖）、银行卡号（BIN + Luhn 验算）、电子邮箱
- ✅ 中文姓名（**语境驱动**：角色标签「原告/被告人/负责人/法定代表人/总经理/审判长…」、称呼、`，男｜女` 结构、职业前缀、强敏感信息邻近、明确谓语「与李四商议」「李四同意」）
- ✅ 姓名传播：同一文档内首次锚定后，后文只出现名字也会命中；同一批次（如整套卷宗）内跨文件传播
- ✅ **位置信息**：按居民身份证地址格式匹配（省→市→县/区→镇/乡/街道→村/社区 行政区划链 + 道路/小区落点 + 门牌楼栋），户籍所在地 / 住址 / 住 / 位于… 引导词可选定位；纯行政区划、无落点要素的叙述不屏蔽；地址统一为「某省/市/县/区/镇/乡/街道 …… 尾字」形态（尾字与层级同字时省略中段，如「浙江省…201室」→「某省……室」）
- ✅ 机构名（律所 / 公司 / 机关 / 医院 / 学校…）：从主体后缀向左取字号，遇虚词、动词、时间词立即截断，跨越短括注（「盛景（南京）…」）与连接词（和/与）精确回溯；**只屏蔽含省/市/县/区/镇/村层级信息的机构**（字号内层级字优先，省份全名/直辖市/主要城市词典兜底，如「江西九洲…」→某省、「盛景（南京）…」→某市），无层级信息的机构一律不屏蔽；统一屏蔽为「某省/市/县/区/镇/村 …… 机构后缀」，不再按原值长度分档
- ✅ 护照号、车牌号、案号、执业证号
- ✅ **默认开启的检测项**：固定电话/传真（含 400 热线）、统一社会信用代码（GB 32100 校验码验算）
- 🔲 **可选检测项（默认关闭，在「设置 → 检测项」中勾选开启）**：微信号/QQ 号（关键词引导，聊天记录场景建议开启）、港澳台证件（回乡证/台胞证）
- ❌ **不屏蔽**：性别、年龄、出生日期、民族（依法判断需要的数据）
- ❌ **不按姓名屏蔽**：机构名与地名（「广东雷阳律师事务所」「雷州市北和镇…村民委员会」），避免把 `雷州市` 误切成 `雷*市`；国家机关、学校、医院名称中的行政区划按设计保留（否则文书不可读），如 `杭州市人民检察院`
- ❌ 误报控制：无语境的姓名（如"今天上午和张伟开会"）不会误屏蔽；`开庭`、`许可`、`教务处`、`司总` 等固定用语不会被当成名字

## 运行

```bash
npm install
npm start        # 启动灵动岛
npm test         # 核心引擎单元测试
```

- **Windows**：双击 [启动灵屿岛.bat](启动灵屿岛.bat)
- **macOS**：首次执行 `chmod +x 启动灵屿岛.command`，之后双击即可（或 `npm start`）

**启动脚本**直接调用 Electron 运行时，不经过 npm。首次使用前需 `npm install`（Electron 下载慢可设镜像：`ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install`）。

## 打包与目录约定

```bash
npm run dist            # 打包当前版本，产物统一放进 release/v<version>/
npm run clean:release   # 只整理 release：删除历史产物，保留当前版本目录
```

- `scripts/dist.js` 按 `package.json` 的版本号生成 `release/v<version>/`，复用本地 Electron 并走国内镜像；安装包、zip、blockmap、`latest.yml`、`win-unpacked` 全部留在该目录内，**`release` 根目录不再散落文件**。
- 每次打包前会清理历史产物，只保留当前版本；被进程占用而删不掉的文件会跳过并打印路径，重启后执行 `npm run clean:release` 即可清掉。
- 不要直接运行 `npx electron-builder --win`，否则会按 `build.directories.output` 把产物倒进 `release` 根目录。

## 使用说明

1. **智能处理**：拖入文件 → 自动识别内容；明文生成 `文件名_屏蔽.ext`，含屏蔽编码的文件生成 `文件名_还原.ext`。根目录只留结果文件，不会复制一份原文件进去，胶囊与面板都会提示完成结果
2. **还原文件**：把已屏蔽文件重新拖入即可，无需手动选择操作；自动还原要求文件内的编码在映射库中可查到，或文件名带 `_屏蔽` / `_还原` 后缀。只有编码外观而库里无记录的普通文件会按明文屏蔽（例如测试文档里的 `〔姓名·abcdef〕`），这类内容可在「文本恢复」页粘贴后手动还原
3. **还原文本**：从文件里复制了被屏蔽的内容 → 胶囊提示「识别到含屏蔽信息」，点右侧「还原文本」按钮即可（点胶囊其他位置只展开面板）；或在「文本恢复」页粘贴
4. **快速查找**：展开面板「快速查找」→ 输入文件名 → 点类别按钮筛选（按钮数字为该类别命中数，类别栏聚焦后可用 ←→ 切换）→ 回车打开 / Shift+回车 定位
5. **同名文件**：「设置 → 同名文件」选择策略，作用于生成的 `_屏蔽` / `_还原` 结果文件。「保留两份」（默认）在结果同名时自动加序号（如 `_屏蔽_02`），旧结果不动；「覆盖同名」直接更新那份结果（启用时有二次确认）
6. **命名归位**：还原产物（`A_还原.docx`）再次拖入屏蔽时，结果回到原名 `A_屏蔽.docx`（同名按上面的策略处理），不会出现 `A_还原_屏蔽.docx`
7. **设置**：检测项开关、剪贴板识别、自动收起（时长可自定义 5–3600 秒，也可选快捷预设，修改后立即生效；**关闭自动收起后，鼠标点击面板外任意位置即收起面板**）、开机自启、清空记录

## 隐私与安全

- 屏蔽映射库（编码 ↔ 原文）仅存本机 `%AppData%`，经 Windows DPAPI（safeStorage）**加密落盘**
- 工具完全不联网，无任何数据上传
- 清空记录不影响已生成的文件与映射库；映射库在「设置 → 数据」中可见加密状态

## 老式 .doc / .dot 支持

拖入 Word 97–2003 的二进制 `.doc` 即可直接处理，无需手动另存：导入时程序会用本机的 **Microsoft Word（Windows COM）或 LibreOffice** 在后台转成临时 `.docx`，再走同一套屏蔽/还原管道。转换全程在本地完成，不联网、不上传，**原 .doc 文件永不改动**（先复制成临时副本再转换）。

- 结果文件是 `.docx`：`阅卷笔录.doc` → `阅卷笔录_屏蔽.docx`，再拖回 → `阅卷笔录_还原.docx`。屏蔽值形如 `138****5678〔手机号·a3f2b1〕`，比原文长，老 `.doc` 的文本按 piece table 分段存储，变长替换必须重建偏移表，容易损坏文档，因此不写回二进制原件。
- 需要本机装有 Word 或 LibreOffice；两者都没有、或文档加密/损坏导致转换失败时，会明确提示「请在 Word 中另存为 .docx」，不会静默丢弃，也不会把处理失败的原文件移入回收站。
- 后缀是 `.doc` 但内容其实是 OOXML（被改过后缀的 docx）会直接按 docx 处理。

## 规则精度

Word 常把一个词拆进多个 `<w:t>`（尤其从老 `.doc` 转出的 docx）：「日出生，公民身份号码」|「 330106199001015670」，「…文三路」|「138」|「号」|「3」|「幢」|「201」|「室」。逐节点独立检测会让关键词引导、地址正则、姓名语境全部在节点边界断裂。

现在按**段落级拼接**统一检测：同一 `<w:p>` / `<a:p>` / `<si>` / `<c>` 内的文本节点无缝拼成一段逻辑文本，再把「原文区间 → 屏蔽值」的编辑映射回各节点。跨节点实体按节点边界拆成片段、各自独立编码（呈现为「〔类型·编码〕」占位），标签与 run 结构一律不动；拼接后的可见文本与直接对整段做屏蔽完全一致，且还原后每个节点都能逐字节复原。

机构名与地址的屏蔽值统一为「某X + `……` + 尾段 + 〔类型·编码〕」形态（机构尾段为后缀，地址尾段为末字；X 取最高行政层级），还原正则因此能精确对齐起点，不会把「户籍所在地」这类正文一起替换掉；也不再保留字号前两字，避免把人名首字留在脱敏产物里。

## 已知限制

- 命名规则统一：屏蔽产物一律为「原文件名_屏蔽」，还原产物一律为「原文件名_还原」，不因文件类型而有例外。PDF / 图片的 `_屏蔽` 产物为不可逆遮盖，无法还原
- PDF 为**不可逆遮盖**：文本 PDF 用文本层坐标定位敏感内容；图片/扫描 PDF 用内置 RapidOCR-json 识别后定位。敏感区域画黑框后整页栅格化，产物为纯图像 PDF，无文本层、不支持还原，也不会写入映射库。重复拖入 `_屏蔽` 文件或状态库命中的产物会跳过，不会二次遮盖。OCR 引擎（含中文/繁中/英/日/韩/俄模型）已随应用打包，解压即用；高级用户可在 `%AppData%` 的 `settings.json` 里用 `pdfRedact.ocrEngineDir` 指定外部引擎目录覆盖内置引擎，`pdfRedact.dpi` 控制清晰度（默认 200）
- 图片（jpg/jpeg/png/webp/bmp/gif/tif）为**不可逆遮盖**：内置 OCR 识别图中文字并定位敏感区域，画黑框后重新编码输出 `_屏蔽` 图片，原图 EXIF/元数据全部丢失，不支持还原、不写映射库。无敏感信息时跳过不产出；OCR 依赖与 PDF 共用同一套引擎。姓名识别依赖语境或同批文件的实体表，孤立出现的姓名可能漏检
- 手写体（如书法、笔迹）的 OCR 识别率较低，可能漏检或误判，重要场景请人工复核
- 段落**内部**跨 run 的敏感值已支持；若关键词与数值被拆到两个不同段落（如段末「公民身份号码」、下一段段首才是号码）仍可能漏检
- 国家机关 / 学校 / 医院名称中的行政区划（如 `杭州市人民检察院`）按设计保留，具体住址、籍贯、连续行政区划链则整串屏蔽
- 中文姓名为语境驱动识别：没有任何语境锚点的单次出现（如正文里孤立的「麦穗」）仍可能漏检；反之，紧邻角色标签但其实是普通词的情况已用边界规则过滤
- 身份锚点覆盖四类文书结构：角色词尾（人/员/者/师/长/告/象）、职务与关系名词（总经理/经理/主任/总监/学生/医生…）、姓名字段（`姓名：` 以及 `姓名为`/`客户名称为`/`户名` 这类无冒号写法）、「姓名 + 被 + 谓语」。确认一次后按哈希在同一案卷内传播，其余出现位置无需重复语境
- 姓名识别为语境驱动，不使用姓氏表或姓名白名单：任意 2~8 字汉字（含少数民族长名、间隔号姓名）只要落入人称锚点即可确认。冒号后是「一句话」（含人称代词 / 情态助动词 / 请求语）时按话语处理，不当姓名——这一条替代了以前的姓氏门槛，冷僻姓不再漏检
- 锚点本身也按封闭语法类过滤：`或者 / 接着 / 随着` 等虚词末字与角色词尾（人/员/者/师/长/告/象）同形时不作锚点；角色词后直接跟 `作 / 进行 / 参与 / 予以 / 提出` 这类只带动作宾语的谓语时整段放弃（`被告人作最后陈述` 不会遮成 `作*后`）；三字以上姓名不以单字虚词（因/由/被/向/对/经/从…）收尾；「宣告/告知/报告」这类告尾动词不作锚点
- 误检可通过「还原」无损找回；漏检建议在屏蔽后人工复核正文中出现的人名
- 屏蔽值还原依赖映射库：请勿删除 `%AppData%` 下的映射库文件
